# Mock Windows EXE와 홈페이지 배포 설계

작성일: 2026-09-29

상태: 사용자 승인 완료, 구현 계획 작성 전 검토 기준

---
## 1. 목적

현재 Text-Play 웹 MVP를 외부 서버 없이 실행할 수 있는 Windows 미리보기 프로그램으로 만든다. 사용자는 Mock 캐릭터와 Mock AI 응답으로 새 게임, 선택지, 자유 입력, 저장과 이어하기를 확인할 수 있어야 한다.

완성된 설치 EXE는 Text-Play GitHub Release에 게시한다. ChatBot 작업에는 버전과 파일 정보를 공유하고, 실제 홈페이지 다운로드 버튼 연결은 HomePage 작업이 담당한다.

---
## 2. 1차 완료 결과

- Windows 10·11 x64용 Tauri 2 미리보기 프로그램
- 외부 서버·로그인·결제 없이 동작하는 강제 Mock 모드
- Text-Play 홈, 새 게임, 이어하기와 플레이 화면
- 선택지, 제한형 자유 입력, 장면·상태·인벤토리 표시
- 자동 저장 1개와 수동 저장 3개
- 앱 종료 후 저장 데이터 복원
- GitHub Release의 설치 EXE와 SHA-256 파일
- HomePage 작업이 바로 사용할 수 있는 다운로드 전달 정보

---
## 3. 범위 제외

- 실제 LLM API와 이미지 생성 API
- 회원가입, 로그인, 서버 크레딧과 결제
- `.mateplay` 외부 콘텐츠 설치·삭제·업데이트
- 클라우드 저장과 다중 기기 동기화
- 자동 업데이트
- 코드 서명 인증서
- macOS와 Linux 패키지

미리보기 EXE는 코드 서명이 없으므로 Windows SmartScreen 경고가 나타날 수 있다. 홈페이지 다운로드 영역과 Release 설명에 이 제한을 명시한다.

---
## 4. 데스크톱 아키텍처

Tauri 2가 Windows 창, 프로그램 수명 주기와 설치 EXE 생성을 담당한다. 데스크톱 화면은 별도 Vite·React 진입점으로 빌드하며 기존 Text-Play 도메인 코드와 화면을 재사용한다.

Next.js 전체 앱을 정적 출력하지 않는다. 현재 앱에는 동적 캐릭터 경로와 서버 전용 `/api/llm` 경로가 있어 전체 정적 출력은 웹 기능과 충돌하기 때문이다.

구조는 다음과 같이 분리한다.

- 기존 Next.js 앱: 웹 실행과 실제 서버 연결 경계 유지
- 데스크톱 Vite 진입점: Text-Play 홈과 플레이 화면만 제공
- 공유 Text-Play 모듈: 게임 엔진, Mock 어댑터, 세션, 저장 계약과 UI
- 플랫폼 어댑터: 화면 이동과 장면 이미지 표시의 Next.js 의존성 제거
- Tauri 셸: Vite 결과물을 로컬 자산으로 로드

데스크톱 빌드는 `NEXT_PUBLIC_LLM_MODE` 값을 읽지 않고 Mock 어댑터를 명시적으로 주입한다. 환경 변수 실수로 외부 LLM을 호출할 수 없어야 한다.

---
## 5. 화면 이동

데스크톱에는 두 화면만 둔다.

1. Text-Play 홈
2. 샘플 게임 플레이

새 게임은 빈 초기 상태로 플레이 화면을 연다. 이어하기는 자동 저장 슬롯을 먼저 읽고 존재할 때만 플레이 화면을 연다. 플레이 화면의 뒤로 가기는 Text-Play 홈으로 돌아간다.

Next.js의 `Link`, 동적 URL과 서버 라우팅은 데스크톱 진입점에서 사용하지 않는다. 화면 상태와 브라우저 히스토리를 연결하는 작은 데스크톱 내비게이션 어댑터를 사용한다.

---
## 6. Mock 데이터와 오프라인 경계

- 샘플 작품은 기존 `DEMO_TEXT_PLAY_PACKAGE`를 사용한다.
- 자유 입력 응답은 기존 `MockLLMAdapter`를 사용한다.
- 장면과 캐릭터 이미지는 프로그램 내부 자산으로 포함한다.
- HTTP LLM 어댑터와 `/api/llm`은 데스크톱 번들에서 사용하지 않는다.
- CSP의 외부 연결을 차단해 의도하지 않은 네트워크 요청을 막는다.

Mock 응답이 실패하거나 잘못된 액션을 반환하면 현재 확정 게임 상태를 유지하고 다시 시도 안내를 표시한다.

---
## 7. 저장 방식

1차 버전은 현재 검증된 IndexedDB 저장소를 Tauri WebView2 프로필 안에서 사용한다. 저장 키와 슬롯 형식은 웹 MVP와 동일하게 유지한다.

- 자동 저장: `auto`
- 수동 저장: `manual-1`, `manual-2`, `manual-3`
- IndexedDB 사용 불가: 현재 실행 중에만 유지되는 메모리 저장소와 경고 표시

저장 파일 직접 내보내기와 Tauri 네이티브 파일 저장소는 `.mateplay` 규격 단계로 미룬다. 설치 제거 시 WebView 데이터가 삭제될 수 있다는 점을 미리보기 안내에 명시한다.

---
## 8. Windows 패키지

- 프레임워크: Tauri 2
- 대상: Windows 10·11 x64
- 번들 형식: NSIS 설치 EXE
- 제품 이름: `MATE Text-Play Preview`
- 초기 버전: `0.1.0-preview.1`
- 설치 파일 이름: `MATE-Text-Play-Preview_0.1.0-preview.1_x64-setup.exe`
- WebView2: 설치 과정에서 런타임 확인 후 필요 시 부트스트래퍼 사용

아이콘은 기존 브랜드 자산을 Windows 아이콘 규격으로 변환해 사용한다. 실행 직후 Text-Play 홈이 열리며 개발자 도구는 배포 빌드에서 비활성화한다.

---
## 9. GitHub Release 배포

Text-Play 저장소에 시험판 Release 태그 `v0.1.0-preview.1`을 만든다. Release에는 다음 파일을 첨부한다.

- `MATE-Text-Play-Preview_0.1.0-preview.1_x64-setup.exe`
- `MATE-Text-Play-Preview_0.1.0-preview.1_x64-setup.exe.sha256`

Release 설명에는 지원 운영체제, Mock 전용 상태, 설치 방법, SmartScreen 가능성, 저장 데이터 제한과 알려진 문제를 기록한다. 홈페이지는 저장소 파일이 아니라 Release 자산 URL을 다운로드 주소로 사용한다.

---
## 10. 작업 간 전달 계약

Text-Play 작업은 EXE 검증 후 다음 정보를 ChatBot 작업과 HomePage 작업에 전달한다.

- 제품명과 표시 버전
- GitHub Release 페이지 URL
- 설치 EXE 직접 다운로드 URL
- 파일 크기
- SHA-256 값
- 지원 운영체제와 아키텍처
- Mock 전용·미서명 시험판 안내 문구
- 검증 일시와 검증한 사용자 흐름

ChatBot 작업은 해당 정보를 서비스 간 연결 참고 자료로 보관한다. HomePage 작업은 전달 정보를 사용해 다운로드 버튼, 버전 표시, 파일 크기, 시스템 요구사항과 시험판 경고를 구현한다.

EXE 파일 자체를 ChatBot 또는 HomePage Git 저장소에 커밋하지 않는다.

---
## 11. 오류 처리

- 저장 실패: 플레이를 유지하고 저장 실패 안내 표시
- 저장 데이터 손상: 해당 슬롯을 열지 않고 새 게임 진입 제공
- Mock 응답 실패: 확정 상태 유지와 동일 입력 수동 재시도
- 필수 자산 누락: 패키징 검증 실패로 처리하고 Release 금지
- WebView2 실행 실패: 설치 안내와 공식 WebView2 설치 경로 표시
- Release 업로드 실패: 로컬 결과물을 보존하고 홈페이지 전달 금지
- 다운로드 검증 실패: 다운로드 버튼 공개 금지

---
## 12. 보안과 개인정보

- API 토큰과 실제 서버 주소를 데스크톱 번들에 포함하지 않는다.
- Mock 모드에서 외부 네트워크 요청을 만들지 않는다.
- 파일 시스템, 셸 실행과 임의 URL 열기 권한을 기본 허용하지 않는다.
- Tauri 권한은 창 표시와 앱 실행에 필요한 최소 범위만 사용한다.
- 사용자 저장 데이터는 로컬 WebView 저장소 밖으로 전송하지 않는다.

---
## 13. 검증 기준

자동 검증:

- 기존 Vitest 전체 통과
- TypeScript 검사 통과
- ESLint 통과
- 데스크톱 Vite 빌드 통과
- Tauri Rust 검사와 Windows 번들 생성 통과
- 데스크톱 모드 외부 요청 차단 테스트 통과

수동 검증:

- 지원 대상 Windows 환경에서 설치와 실행
- Text-Play 홈 표시
- 새 게임, 선택지와 자유 입력 진행
- 자동 저장과 수동 저장
- 앱 종료 후 이어하기
- CSP·정적 번들 검사와 런타임 요청 감시로 외부 연결 부재 확인
- 제거·재설치 시 저장 데이터 동작 확인
- Release에서 내려받은 EXE의 SHA-256 일치
- 홈페이지 다운로드 버튼으로 실제 파일 다운로드

승인된 자동 대체 검증을 포함해 하나라도 실패하면 Release를 공개하지 않는다.

---
## 14. 구현 순서

1. Windows 빌드 도구와 Tauri 기반 구성
2. 데스크톱 Vite 진입점과 플랫폼 어댑터
3. 강제 Mock 모드와 외부 연결 차단
4. 저장·재실행 검증
5. Windows 설치 EXE 생성
6. 로컬 설치와 오프라인 검증
7. GitHub Release 게시와 해시 확인
8. ChatBot·HomePage 작업에 전달
9. HomePage 다운로드 버튼 구현과 실제 다운로드 검증

Text-Play 구현 계획은 1~8단계를 담당한다. 9단계는 HomePage 저장소에서 별도 설계와 구현 계획으로 진행한다.
