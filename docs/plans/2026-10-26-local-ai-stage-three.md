# 3단계 — 내장 AI 다운로드와 실제 응답 검증

기준 커밋은 `2a101cf`입니다. 사용자가 설명한 다음 단계의 진행을 지시했으므로 별도 승인 질문 없이 구현하고 검증 후 `main`에 커밋·푸시합니다.

---
## 현재 상태와 구현 범위

모델 관리 화면, Rust 다운로드·이어받기·해시 검사, Vulkan 실행과 CPU 대체, JSON 응답 제약은 이미 있습니다. 다운로드 정보가 비어 있고 실행 엔진이 설치 파일에 포함되지 않아 새 PC에서 바로 준비할 수 없습니다. 기존 기능을 연결하고 실제 모델 응답을 측정합니다.

모델 원본을 모두 내려받아 새 양자화를 만들면 현재 약 33GiB의 디스크 여유로 원본·출력·측정 파일을 함께 유지하기 어렵습니다. 이번에는 원본과 배포자를 구분한 고정 GGUF 배포본을 사용합니다. 가벼움은 mykor의 Mi:dm Mini, 표준·고성능은 Unsloth의 원본 Qwen3.5 4B·9B Q4_K_M 파일입니다. 공식 원본의 라이선스와 배포 파일의 리비전·바이트 크기·SHA-256을 확인하고 출처를 기록합니다. 변형·검열 해제 모델은 사용하지 않습니다.

앱을 설치한 뒤 AI 모델 화면에서 모델을 받고 선택하는 흐름을 완성합니다. 대용량 모델을 알림 없이 자동 다운로드하지 않습니다. 설치 직후의 별도 자동 준비 마법사는 이후 배포 단계로 남기되, 실행 엔진은 EXE 설치 묶음에 포함합니다. 모델은 업데이트와 별개로 사용자 폴더에 보관합니다.

---
## 작업 순서

1. 세 모델의 고정 다운로드 계약과 라이선스 기록에 대한 실패 테스트를 작성합니다. 검증된 주소·크기·SHA-256으로 카탈로그를 연결합니다.
2. 같은 카탈로그를 사용하는 개발용 모델 준비 도구와 평가 manifest를 연결합니다. 이미 받은 파일도 검사하고 중복 다운로드를 피합니다.
3. 고정 Vulkan·CPU 실행 엔진과 필수 고지문을 설치 자산으로 준비하는 도구를 추가합니다. 새 복제본 빌드에서도 같은 파일을 포함합니다.
4. 실제 모델을 내려받아 GPU·CPU의 장면 응답을 측정합니다. 평가 문맥이 확장 작품과 맞는지 확인하고 숨겨진 사건·스포일러·허용하지 않은 상태 변경을 점검합니다.
5. 화면의 다운로드·취소·재개·모델 선택·실패 안내를 검증합니다. 엔진·모델 누락, 연결 실패, CPU 대체와 기존 저장을 확인합니다.
6. 전체 자동 테스트·Rust 테스트·웹/데스크톱 사용자 흐름·Windows 빌드를 수행하고 독립 검토의 중요 문제를 회귀 테스트로 수정합니다. 모델별 실제 측정과 미검증 범위를 문서에 남깁니다.

---
## 완료 기준

새 EXE가 실행 엔진을 포함하고 모델 관리 화면에서 준비 가능한 모델의 다운로드와 선택이 동작해야 합니다. 다운로드는 고정 파일만 받고 해시가 다르면 사용하지 않아야 합니다. 실제 장면 문맥으로 모델 응답을 생성하고 형식·허용 행동·속도·메모리를 기록합니다. 한 PC의 측정 결과를 모든 PC의 성능이나 한국어 품질 합격으로 일반화하지 않습니다. 실패 시 저장 상태를 유지하고 재시도 또는 임시 AI 선택을 제공해야 합니다.
