# 2단계 대표 작품 개발 계획

사용자가 승인한 개발 방향에 따라 추가 승인 대기 없이 구현합니다. 기준 소스는 `2eb6464`이며 작업 브랜치는 `main`입니다.

---
## 작품과 구현 방향

기존 `달빛 숲의 기록`을 18개 장면으로 확장합니다. 리라는 숲의 기록관이며 숲 아래 목소리는 오래된 구조 신호라는 설정을 유지합니다. 선택지의 결정형 진행을 기반으로 하고 자유 입력은 현재 장면 안의 관찰·대화에 사용합니다.

장면 흐름: 숲 입구 → 폐허 회랑 → 봉인 서재 → 기록관의 편지 → 뿌리 갈림길 → 호수·물 위의 기억 또는 종탑·마지막 종소리 → 잠긴 계단 → 기록고 문 → 지하 기록고 → 리라의 기억 → 숲의 심장 → 마지막 봉인 → 기록을 돌려주는 길 → 진실 엔딩. 입구나 마지막 봉인에서 돌아가는 엔딩도 가능합니다.

과거 장면·선택지·엔딩 ID와 저장 스키마를 유지하고 작품 버전만 0.2.0으로 올립니다. 새 로그에 장면 ID를 저장해 턴 이미지 연결을 명확하게 하고 과거 서술 기반 기록도 계속 해석합니다. 새 선택지 조건은 선택지를 숨기는 것과 엔진의 직접 호출 거부에 같은 규칙을 적용합니다. 모든 경로에 조건 없는 진행 또는 귀환 선택지를 둡니다.

장면마다 목표·등장인물 대사·추천 관찰 문구를 제공하고 아이템·퀘스트는 진행 요약에서 확인합니다. 한국어와 영어를 함께 작성합니다. 장면 이미지는 이미지 생성 도구로 제작한 환경 그림 10개를 여러 시점에 연결하며, 각 엔딩에는 별도 그림을 사용합니다. 준비 중 작품은 공개 예정 영역으로 분리하고 플레이 수·인기 순위처럼 보이는 임의 수치는 제거합니다.

---
## 작업 순서와 검증

1. 실패 테스트로 15~20장면·분기 도달성·조건 거부·원자성·옛 저장 호환·턴 이미지와 대사 기록을 정의합니다.
2. 작품 데이터·영어판·선택 조건·장면 기록을 구현하고 전체 경로를 탐색해 막힌 장면이 없는지 검증합니다.
3. 진행 요약·장면별 추천·준비 중 작품 분리를 구현하고 화면·언어·접근성 테스트를 확인합니다.
4. 생성 그림을 저장소로 복사하고 경로·오프라인 자산·실제 이미지 파일을 검증합니다. 생성 프롬프트는 별도 자산 기록에 보관합니다.
5. 전체 테스트·타입·린트·웹 및 데스크톱 E2E·Windows 빌드를 검증합니다. 기존 짧은 경로를 가정한 테스트는 새 실제 경로를 검증하도록 갱신합니다.
6. 독립 최종 검토 후 문서·인수인계를 갱신하고 한국어 메시지로 main에 커밋·푸시합니다.

---
## 완료 기준

정상 경로가 3번 선택으로 끝나지 않고 두 탐색 경로에서 엔딩까지 도달해야 합니다. 모든 장면이 번역·대사·목표·존재하는 정식 이미지를 갖고, 중간 저장 후 복원과 과거 턴 열람에서도 내용·상태·이미지가 일치해야 합니다. 외부 AI 없이 임시 AI와 선택지만으로 완료할 수 있어야 합니다.
