# AI 캐릭터·스토리 채팅 서비스 UI 기반 설계

작성일: 2026-09-22

상태: 사용자 승인 완료 설계

대상 저장소: `siwoo440/ChatBot`

## 1. 목적

이 프로젝트의 1차 목표는 감정 교류형 AI 동반자와 가벼운 스토리 경험을 제공하는 웹 서비스의 화면 기반을 만드는 것이다.

사용자는 공개 캐릭터를 탐색하고, 캐릭터 상세 정보를 확인하고, 대화를 시작하고, 자신만의 캐릭터를 제작할 수 있어야 한다.

이번 범위에서는 실제 LLM, 이미지 생성, Supabase, 결제 API를 호출하지 않는다.

화면과 상태 흐름은 Mock 데이터로 완전히 체험할 수 있어야 하며, 향후 실제 서비스 어댑터로 교체할 수 있는 경계를 준비한다.

## 2. 성공 기준

- API 키 없이 전체 화면이 실행된다.
- 외부 AI, 이미지 생성, 데이터베이스, 결제 요청이 발생하지 않는다.
- 탐색, 캐릭터 상세, 채팅, 캐릭터 제작, 내 작품, 설정 화면을 이동할 수 있다.
- Mock 캐릭터 응답, 장면 전환, 관계 변화, 가상 토큰 차감이 작동한다.
- 대화와 설정이 새로고침 후에도 브라우저에 유지된다.
- 모바일, 태블릿, 모니터별 세 가지 레이아웃과 자동 추천이 작동한다.
- 데스크톱 좌우 패널과 모바일 서랍 패널이 키보드와 포인터로 동작한다.
- 실제 공급자 연결 시 화면 컴포넌트를 변경하지 않고 어댑터만 교체할 수 있다.

## 3. 이번 범위에서 제외되는 기능

- 실제 OpenAI, Anthropic 또는 기타 LLM 호출
- 실제 이미지 생성 호출
- Supabase 프로젝트 연결과 원격 데이터 저장
- 실제 로그인과 소셜 로그인
- 실제 결제, 구독, 환불, 제작자 정산
- 실제 웹 푸시와 모바일 푸시 알림
- 사용자 간 실시간 메시지
- 운영자 신고 처리와 콘텐츠 심사 도구
- PC용 로컬 모델 다운로드와 실행

제외 기능의 버튼이나 진입점은 비활성 또는 준비 중 상태로 표현할 수 있지만 외부 요청을 발생시키면 안 된다.

## 4. 디자인 방향

### 4.1 참고 구조

- 데스크톱은 좌측 대화 목록, 상단 탐색, 검색, 카테고리, 추천 배너, 가로형 캐릭터 목록으로 구성한다.
- 모바일은 상단 홈·랭킹, 프로모션 배너, 세로 이미지 2열 카드, 하단 고정 메뉴로 구성한다.
- 경쟁 서비스의 로고, 캐릭터 이미지, 문구, 고유 아이콘은 복제하지 않는다.
- 정보 구조와 상호작용 원칙만 참고하고 자체 브랜드와 자체 콘텐츠를 사용한다.

### 4.2 시각 원칙

- 기본 테마는 어두운 배경과 높은 대비의 카드 이미지 중심 구성이다.
- 핵심 강조색은 하나만 사용하고 선택 상태, 주요 버튼, 진행 상태에 일관되게 적용한다.
- 캐릭터 카드에는 대표 이미지, 이름, 한 줄 소개, 인기 또는 대화 지표만 우선 노출한다.
- 긴 설명은 상세 페이지로 이동시켜 탐색 화면의 밀도를 유지한다.
- 이미지가 없는 상태에서도 레이아웃이 무너지지 않도록 그라데이션 대체 이미지를 제공한다.

## 5. 정보 구조와 경로

| 경로 | 역할 | 주요 진입점 |
| --- | --- | --- |
| `/` | 캐릭터 탐색 홈 | 최초 진입, 홈 메뉴 |
| `/characters/[id]` | 캐릭터와 세계관 상세 | 탐색 카드 |
| `/chat/[characterId]` | 핵심 채팅 화면 | 대화 시작, 좌측 대화방 |
| `/characters/new` | 캐릭터 제작 | 만들기 버튼 |
| `/characters/[id]/edit` | 캐릭터 수정 | 내 작품 관리 |
| `/library` | 내 작품과 보관함 | 상단 메뉴, 사용자 패널 |
| `/settings` | 프로필·알림·레이아웃 설정 | 사용자 패널 |

기본 흐름은 `탐색 → 상세 → 대화 시작 → 대화방 생성 → 채팅`이다.

좌측 대화방 항목은 기존 `/chat/[characterId]`로 직접 이동한다.

오른쪽 사용자 패널은 설정과 내 작품으로 연결하되 패널 내부에서 모든 복잡한 편집을 처리하지 않는다.

## 6. 공통 애플리케이션 셸

### 6.1 데스크톱

화면은 `왼쪽 대화방 패널 + 중앙 콘텐츠 + 오른쪽 사용자 패널`의 세 영역으로 구성한다.

기본 상태는 왼쪽 패널 열림, 오른쪽 패널 닫힘이다.

상단의 왼쪽 패널 버튼과 사용자 프로필 버튼으로 각각 독립적으로 열고 닫는다.

패널이 닫히면 중앙 콘텐츠가 남은 공간을 차지하며 빈 여백을 남기지 않는다.

두 패널을 동시에 열 수 있지만 중앙 콘텐츠의 최소 가독 폭을 보장한다.

중앙 콘텐츠가 최소 폭 이하가 되는 화면에서는 오른쪽 패널을 오버레이 방식으로 전환한다.

### 6.2 모바일

기본 상태에서 좌우 패널은 모두 닫혀 있다.

왼쪽 버튼은 대화방 서랍을, 오른쪽 프로필 버튼은 사용자 서랍을 연다.

서랍은 화면 위로 슬라이드되며 배경을 어둡게 처리한다.

한 번에 하나의 서랍만 열 수 있다.

닫기 버튼, 배경 선택, Escape 키로 닫을 수 있다.

서랍이 열린 동안 뒤쪽 본문 스크롤과 포커스 이동을 제한한다.

### 6.3 왼쪽 대화방 패널

- 진행한 대화방 목록
- 캐릭터 프로필 이미지
- 대화방 또는 캐릭터 이름
- 마지막 메시지 미리보기
- 마지막 활동 시각
- 현재 선택된 대화방 표시
- 새 캐릭터 만들기
- 대화 정리
- 보관함

목록은 최근 활동 순으로 정렬하며 항목이 많아지면 패널 내부만 스크롤한다.

### 6.4 오른쪽 사용자 패널

- 사용자 프로필과 멤버십
- 보유 가상 토큰
- 오늘의 이미지 생성 횟수
- 프로필 관리
- 내 캐릭터와 작품
- 토큰 이용 내역
- 화면 레이아웃
- 알림 허용 시간
- 캐릭터 선제 메시지 설정
- 개인정보 및 보안
- 고객 지원
- 로그아웃

로그아웃은 Mock 환경에서 확인 대화상자를 표시한 뒤 로컬 세션 상태만 초기화한다.

대화 기록과 제작 데이터는 로그아웃만으로 삭제하지 않는다.

## 7. 반응형 레이아웃 체계

### 7.1 플랫폼 판정

- 모바일: 좁은 화면 중심
- 태블릿: 중간 폭과 세로·가로 방향 고려
- 모니터: 넓은 화면과 초광폭 비율 고려

사용자는 자동 판정을 유지하거나 플랫폼과 해상도를 강제로 선택할 수 있다.

설정값은 브라우저에 저장한다.

### 7.2 레이아웃 목록

| ID | 플랫폼 | 설명 | 추천 조건 |
| --- | --- | --- | --- |
| M1 | 모바일 | 균형형 세로 배치 | 모바일 세로 화면 |
| M2 | 모바일 | 장면 이미지 강조 | 이미지 중심 수동 선택 |
| M3 | 모바일 | 채팅 영역 강조 | 모바일 가로 화면 |
| T1 | 태블릿 | 장면과 채팅 가로 분할 | 태블릿 가로 화면 |
| T2 | 태블릿 | 중앙 세로 집중 | 태블릿 세로 화면 |
| T3 | 태블릿 | 장면과 정보 강조 | 정보 중심 수동 선택 |
| D1 | 모니터 | 중앙 집중형 | 일반 모니터 |
| D2 | 모니터 | 3열 정보형 | 폭 1600px 이상 |
| D3 | 모니터 | 시네마틱 장면형 | 화면 비율 1.9 초과 |

자동 추천 결과는 사용자가 변경할 수 있으며 사용자 선택이 자동 추천보다 우선한다.

## 11. 상태와 저장 구조

전역 상태는 React Context와 `useReducer`로 구성한다.

이번 규모에서는 별도 상태 관리 라이브러리를 추가하지 않는다.

저장은 Repository 인터페이스 뒤에 배치한다.

- `CharacterRepository`
- `ConversationRepository`
- `SettingsRepository`
- `TokenRepository`

초기 구현은 다음 로컬 저장소를 사용한다.

- `LocalCharacterRepository`
- `LocalConversationRepository`
- `LocalSettingsRepository`
- `LocalTokenRepository`

향후 Supabase 구현은 같은 인터페이스를 사용한다.

화면 컴포넌트는 `localStorage`나 Supabase SDK를 직접 호출하지 않는다.

## 12. Mock 어댑터

### 12.1 LLMAdapter

인터페이스 책임은 메시지 응답, 스트리밍 표현, 대화 요약이다.

초기 구현은 `MockLLMAdapter`만 활성화한다.

Mock 응답은 캐릭터 ID, 현재 감정, 관계 단계, 최근 사용자 메시지를 기준으로 미리 정의된 응답군에서 선택한다.

같은 입력에 대한 테스트가 안정적이도록 난수 대신 선택 가능한 시드 또는 순차 규칙을 사용한다.

실제 공급자 구현 파일은 이번 범위에서 만들지 않거나 네트워크를 호출하지 않는 비활성 골격으로만 둔다.

### 12.2 ImageGenerationAdapter

인터페이스 책임은 장면 생성, 다시 생성, 취소다.

초기 `MockImageAdapter`는 `public/images/scenes`에 포함된 샘플 이미지를 반환한다.

캐릭터와 장면에 적합한 샘플이 없으면 공통 대체 이미지를 반환한다.

### 12.3 공급자 설정

기본 공급자는 항상 `mock`이다.

실제 공급자 활성화 환경변수의 기본값은 `false`다.

브라우저 번들에 비밀키가 포함되지 않도록 실제 키 이름은 `.env.example`에 값 없이 문서화한다.

이번 범위의 테스트는 외부 네트워크 요청이 발생하면 실패해야 한다.

## 13. Mock 대화와 스토리 규칙

1. 사용자가 메시지를 전송한다.
2. 메시지를 로컬 대화방에 저장한다.
3. 가상 토큰을 확인하고 차감한다.
4. Mock 어댑터가 캐릭터 응답을 선택한다.
5. 응답을 순차 출력 형태로 표시한다.
6. 감정과 관계 수치를 갱신한다.
7. 중요 사건 여부를 판정한다.
8. 중요 사건이면 Mock 장면 이미지를 교체한다.
9. 변경된 상태를 저장한다.

관계 단계는 수치와 이름을 함께 가진다.

예시 단계는 `첫 만남 → 아는 사이 → 가까운 사이 → 특별한 사이`다.

부정적인 선택으로 수치가 감소할 수 있지만 초기 데모에서는 관계가 영구적으로 잠기지 않는다.

## 14. 가상 토큰 정책

| 동작 | 차감량 |
| --- | ---: |
| 일반 대화 | 1 |
| 고급 대화 Mock | 3 |
| 중요 사건 자동 이미지 | 15 |
| 수동 이미지 생성 | 20 |
| 이미지 다시 생성 | 20 |

가상 토큰은 실제 화폐 가치가 없으며 결제와 연결하지 않는다.

잔액이 부족하면 동작을 중지하고 요금제 안내 화면을 표시한다.

요금제 안내 화면의 구매 버튼은 준비 중 상태이며 결제 요청을 보내지 않는다.

개발과 테스트를 위한 가상 토큰 충전 버튼은 개발 전용 표시와 함께 제공할 수 있다.

## 15. 알림 준비 상태

이번 범위에서는 실제 알림을 발송하지 않는다.

사용자는 다음 값을 설정할 수 있다.

- 선제 메시지 허용 여부
- 허용 시작 시각
- 허용 종료 시각
- 하루 최대 횟수

설정 미리보기는 현재 관계와 상황에 맞춘 Mock 메시지를 화면 안에서만 보여준다.

실제 브라우저 알림 권한을 요청하지 않는다.

## 16. 오류와 복구

다음 상태에 전용 UI를 제공한다.

- 저장 데이터 없음
- Mock 응답 실패
- Mock 이미지 준비 실패
- 가상 토큰 부족
- 존재하지 않는 캐릭터 경로
- 손상된 로컬 데이터
- 브라우저 저장공간 부족
- 오프라인 상태

손상된 데이터는 즉시 삭제하지 않는다.

복구 가능한 데이터는 정상 구조로 마이그레이션하고, 불가능한 경우 내보내기와 초기화 선택지를 제공한다.

로컬 데이터 삭제는 사용자 확인 후 실행한다.

## 17. 접근성과 상호작용

- 모든 버튼에 접근 가능한 이름을 제공한다.
- 패널 버튼은 `aria-expanded`와 연결 대상을 표현한다.
- 패널 열림과 닫힘은 색상만으로 구분하지 않는다.
- 모바일 서랍은 포커스를 내부에 유지하고 닫힌 뒤 원래 버튼으로 포커스를 돌린다.
- Escape 키로 열린 메뉴와 서랍을 닫는다.
- 메시지 추가와 토큰 부족 상태는 적절한 라이브 영역으로 전달한다.
- 최소 터치 영역은 약 44px을 목표로 한다.
- 애니메이션 감소 설정을 존중한다.
- 이미지에는 캐릭터 또는 장면을 설명하는 대체 텍스트를 제공한다.
