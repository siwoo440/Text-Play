# Text-Play 웹 플레이 MVP 설계

작성일: 2026-09-25

상태: 1단계 구현·검증 완료, 이후 변경 가능

대상 코드: `imports/chatbot-session-snapshot`
후속 목표: 웹 MVP 검증 후 Tauri 기반 Windows 프로그램 패키징

## 1. 문서 목적

기존 Mate Verse ChatBot 웹 앱에 Text-Play 플레이 전용 MVP를 추가한다. 첫 단계에서는 샘플 텍스트 게임 한 편을 웹에서 처음부터 엔딩까지 플레이하고 저장·복원할 수 있게 만든다. 기존 챗봇과 동일한 LLM 호출 경계를 공유하지만 일반 캐릭터 채팅과 게임 상태는 분리한다.

본 설계의 세부 수치와 UI 배치는 이후 사용자 피드백에 따라 변경할 수 있다. 다만 게임 상태의 결정권을 엔진에 두는 원칙, 일반 채팅과 게임 세이브의 분리, LLM 응답 검증은 데이터 안정성과 보안을 위해 유지한다.

## 2. 현재 확인된 기준

- 기존 ChatBot은 Next.js, React, TypeScript로 구성되어 있다.
- 캐릭터 탐색, 상세, 채팅, 보관함, 설정, 로컬 백업·복구가 구현되어 있다.
- `LLMAdapter` 계약과 결정형 `MockLLMAdapter`가 존재한다.
- 실제 운영 LLM 공급자와 서버 API는 아직 연결되지 않았다.
- ChatBot 원본 저장소에는 커밋되지 않은 UI 변경이 있으므로 가져온 스냅샷에서 Text-Play를 격리 개발한다.
- 코드는 Allman 스타일과 각 줄의 짧은 한글 명사형 주석 규칙을 따른다.

## 3. 목표

1. `/text-play`에서 Text-Play 소개와 공식 샘플 게임을 표시한다.
2. `/text-play/demo`에서 Story Mode와 제한형 Hybrid Mode를 제공한다.
3. 선택지만으로도 샘플 게임을 처음부터 엔딩까지 완료할 수 있게 한다.
4. 자유 입력을 기존 `LLMAdapter`로 처리하고 검증된 게임 액션만 반영한다.
5. HP, 정신력, 골드, 위치, 관계도, 인벤토리, 퀘스트를 엔진 상태로 관리한다.
6. 자동 저장 한 개와 수동 저장 세 개를 IndexedDB에 보관한다.
7. 기존 캐릭터 채팅, 지갑, 설정 데이터에 영향을 주지 않는다.
8. 데스크톱, 태블릿, 모바일 웹에서 플레이 가능한 반응형 UI를 제공한다.

## 4. MVP 제외 범위

- Text-Play 제작기
- 공개 마켓과 제작자 페이지
- 유료 패키지, 결제, 정산
- 실제 `.mateplay` 압축 파일 설치
- Sandbox Mode
- 멀티플레이
- 클라우드 세이브와 기기 간 병합
- 로컬 LLM
- 음성 대화와 실시간 AI 이미지 생성
- Tauri Windows 설치 프로그램

제외 기능은 MVP의 데이터와 사용성 검증 이후 별도 설계한다.

## 5. 선택한 구현 접근

기존 ChatBot 앱에 `text-play` 기능 모듈을 추가한다. 앱 전체를 모노레포로 바꾸거나 별도 웹 앱을 만들지 않는다. 현재 구조를 유지하면서 Text-Play의 Core, AI 변환, 저장소, UI를 기능 폴더 안에서 분리한다.

이 접근은 기존 헤더, 테마, 채팅 스트리밍 경험, `LLMAdapter` 계약을 재사용하면서 게임 상태가 기존 `AppState`에 무제한으로 섞이는 것을 방지한다.

## 6. 경로와 화면

### 6.1 `/text-play`

- Text-Play 서비스 설명
- 공식 샘플 게임 카드
- 새 게임과 이어하기 진입점
- 마지막 저장 시각과 진행 요약
- 기존 Mate Verse 탐색 화면으로 돌아가는 경로

### 6.2 `/text-play/demo`

- 상단: 작품명, 현재 장면, 위치, 저장 메뉴, AI 상태
- 중앙: 정적 배경·캐릭터 이미지와 서술·대사 로그
- 하단: 선택지, 자유 입력, 전송, 응답 중지
- 우측 또는 접이식 패널: 상태, 인벤토리, 퀘스트, 관계도
- 모바일: 상태 패널을 별도 서랍으로 전환

### 6.3 저장 관리자

- 자동 저장 한 개
- 수동 저장 세 개
- 슬롯별 장면명, 플레이 시간, 저장 시각, 진행 요약
- 불러오기 전 현재 진행 손실 확인
- 손상된 저장 데이터의 복구 안내

## 7. 기능 모듈

예상 파일 구조는 다음과 같다.

```text
src/features/text-play/
├─ core/
│  ├─ types.ts
│  ├─ engine.ts
│  ├─ conditions.ts
│  ├─ actions.ts
│  └─ save-schema.ts
├─ data/
│  └─ demo-package.ts
├─ storage/
│  └─ indexeddb-save-repository.ts
├─ ai/
│  ├─ context-builder.ts
│  ├─ response-schema.ts
│  └─ action-validator.ts
└─ ui/
   ├─ TextPlayHome.tsx
   ├─ TextPlayScreen.tsx
   ├─ StoryLog.tsx
   ├─ ChoiceList.tsx
   ├─ StatusPanel.tsx
   ├─ InventoryPanel.tsx
   └─ SaveManager.tsx
```

각 모듈은 다음 책임을 가진다.

- Core: 게임 상태, 조건, 액션, 이벤트, 퀘스트, 엔딩 판정
- Data: 샘플 게임의 선언형 데이터
- Storage: 저장 슬롯, 스키마 검사, 복원
- AI: 컨텍스트 구성, 구조화 응답 해석, 액션 검증
- UI: 사용자 입력과 상태 표시

## 8. 게임 상태 모델

샘플 게임 상태는 다음 항목을 포함한다.

- `packageId`, `packageVersion`, `saveSchemaVersion`
- 현재 장면과 위치
- HP, 정신력, 골드
- 주요 NPC 관계도
- 인벤토리 항목과 수량
- 활성·완료 퀘스트
- 이벤트 플래그
- 대화·서술 로그 참조
- 엔딩 상태
- 플레이 시간과 저장 시각

게임 상태의 단일 진실 원천은 Text-Play Engine이다. LLM 기억이나 화면 컴포넌트를 상태 원천으로 사용하지 않는다.

## 9. 플레이 방식

### 9.1 Story Mode

제작된 선택지와 명시적 조건으로 진행한다. AI가 없어도 처음부터 엔딩까지 플레이할 수 있어야 한다.

### 9.2 제한형 Hybrid Mode

자유 입력으로 NPC와 상호작용할 수 있지만 퀘스트, 핵심 사건, 아이템, 엔딩은 엔진 규칙으로 판정한다. 자유 입력이 필수 진행 조건이 되지 않게 한다.

### 9.3 샘플 콘텐츠

첫 샘플은 판타지 미스터리 탐험 장르로 제작한다. 텍스트 중심으로 진행하며 정적 배경과 캐릭터 이미지를 선택적으로 표시한다. 샘플의 고유 설정과 분량은 구현 계획에서 테스트 가능한 최소 규모로 확정한다.

## 10. LLM 연동

Text-Play는 기존 `LLMAdapter` 호출 경계를 공유한다. 현재는 `MockLLMAdapter`를 사용하며 실제 ChatBot 서버 모델이 연결되면 같은 공급자 선택과 스트리밍 경로를 사용한다.

Text-Play 전용 계층은 다음 기능만 담당한다.

1. 현재 장면, 관련 캐릭터, 허용 액션, 상태 요약으로 컨텍스트를 구성한다.
2. 사용자 표시용 `narration`, `dialogue`와 엔진용 `proposedActions`를 분리한다.
3. 응답 스키마를 검사한다.
4. 허용 목록에 포함된 액션만 Action Validator에 전달한다.

실제 공급자 이름, 모델명, API 경로, 비용 정책은 기존 ChatBot의 실제 LLM 연결이 확정된 뒤 같은 설정을 참조한다. 현재는 확인이 필요한 외부 조건이다.

## 11. 액션 검증

초기 허용 액션은 다음 범위로 제한한다.

- 능력치 변경
- 아이템 추가·제거
- 위치 이동
- 관계도 변경
- 이벤트 실행
- 퀘스트 시작·완료

각 액션은 대상 존재 여부, 값 범위, 선행 조건, 현재 장면의 허용 여부를 검사한다. 잘못된 JSON, 존재하지 않는 대상, 범위를 벗어난 값, 허용되지 않은 액션은 상태에 반영하지 않는다. 핵심 이벤트와 엔딩은 LLM 제안만으로 확정하지 않는다.

## 12. 저장 구조

- 게임 저장: IndexedDB
- 화면과 접근성 설정: 기존 localStorage 설정 재사용
- 일반 캐릭터 채팅: 기존 ChatBot 저장 구조 유지
- Text-Play 저장소 키: 작품 ID와 슬롯 ID로 격리
- 저장 시점: 장면 전환, 주요 이벤트, 수동 저장
- 스키마 변경: `saveSchemaVersion` 기반 마이그레이션

저장 데이터가 검증에 실패하면 원본을 덮어쓰지 않고 오류를 표시한다. 사용 가능한 마지막 정상 자동 저장이 있으면 복구 대상으로 제시한다.

## 13. 오류 처리

- LLM 실패: 입력 유지, 비용 차감 금지, 재시도 제공
- 응답 취소: 생성 중인 응답만 중단하고 확정 상태 유지
- 잘못된 액션: 서술과 분리해 액션 적용 거부 표시
- 저장 실패: 플레이 유지, 저장 실패 안내, 재시도 제공
- 저장 손상: 자동 적용 금지, 정상 슬롯 복구 안내
- 데이터베이스 사용 불가: 새 게임 시작 전 제한 안내
- 샘플 데이터 오류: 안전한 오류 화면과 홈 복귀 제공

## 14. 보안과 개인정보

- 브라우저나 향후 Windows 실행 파일에 LLM 비밀키를 포함하지 않는다.
- 실제 AI 요청은 기존 ChatBot 서버 API를 경유한다.
- LLM이 임의 코드, 파일 경로, 네트워크 요청을 실행하지 못하게 한다.
- Text-Play 패키지는 향후 선언형 데이터만 허용한다.
- 전체 대화 내용을 진단 로그에 기본 포함하지 않는다.
- ChatBot 대화 삭제와 Text-Play 저장 삭제를 별도 동작으로 유지한다.

## 15. 접근성과 반응형 UI

- 키보드만으로 선택지, 입력, 저장 메뉴 이동
- 메시지 스트리밍 상태를 보조 기술에 전달
- 글자 크기와 UI 배율 설정 반영
- 애니메이션 감소 설정 반영
- 모바일에서 상태 패널을 서랍으로 제공
- 색상만으로 상태 변화를 전달하지 않음
- 시스템 메시지와 AI 서술을 시각·의미적으로 분리

## 16. 테스트 전략

### 16.1 단위 테스트

- 조건 판정
- 허용 액션과 값 범위 검증
- 퀘스트와 이벤트 전환
- 엔딩 판정
- 저장 스키마 검증과 마이그레이션
- AI 응답 스키마 파싱

### 16.2 통합 테스트

- 새 게임부터 엔딩까지 선택지 플레이
- 자유 입력과 Mock LLM 응답 반영
- 잘못된 proposedActions 차단
- 자동·수동 저장 후 새 인스턴스 복원
- 기존 ChatBot 상태 무변경 검증

### 16.3 UI 테스트

- 데스크톱·태블릿·모바일 레이아웃
- 키보드 탐색
- 스트리밍 중지와 오류 재시도
- 상태·인벤토리·퀘스트 갱신 표시
- 저장 슬롯 확인과 불러오기

## 17. MVP 완료 기준

1. `/text-play`와 `/text-play/demo`가 정상 이동한다.
2. 샘플 게임을 선택지만으로 엔딩까지 완료할 수 있다.
3. 자유 입력이 Mock LLM을 통해 응답되고 검증된 액션만 반영된다.
4. 자동 저장과 수동 저장 세 개가 새로고침 이후 복원된다.
5. 게임 상태와 AI 서술 사이에 치명적 불일치가 없다.
6. Text-Play 실행과 저장이 기존 캐릭터 채팅 데이터에 영향을 주지 않는다.
7. 모바일·태블릿·데스크톱에서 주요 기능을 사용할 수 있다.
8. 관련 단위·통합·UI 테스트와 타입 검사, 린트, 빌드가 통과한다.

## 18. 후속 단계

1. 실제 ChatBot 서버 LLM 연결 공유
2. 내부 JSON 구조를 `.mateplay` 패키지 규격으로 확장
3. 라이브러리와 다운로드·업데이트 화면
4. 기본 제작기
5. 클라우드 세이브와 계정 연동
6. Tauri Windows 프로그램 패키징
7. 제작자 배포와 마켓

## 19. 변경 관리

이 설계는 고정된 최종 사양이 아니다. 사용자 검토와 구현 중 발견 사항에 따라 장르, UI 배치, 능력치, 슬롯 수, 경로, 저장 세부 방식과 모듈 이름을 변경할 수 있다.

변경 시 다음 기준을 적용한다.

- 구현 전 변경: 설계 문서와 구현 계획을 먼저 갱신
- 구현 중 변경: 기존 테스트와 저장 호환성 영향을 확인
- 저장 스키마 변경: 마이그레이션과 이전 데이터 복구 기준 추가
- LLM 응답 변경: 스키마 검증과 Action Validator 테스트 갱신
- 범위 확대: 제작기, 마켓, 결제, Windows 패키징은 별도 단계로 분리

상태 단일 원천, 저장 격리, 비밀키 서버 보관, 선언형 액션 검증은 변경 시에도 기본 안전 경계로 유지한다.
