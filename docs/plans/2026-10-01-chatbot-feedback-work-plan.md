### 1.3 ChatBot의 부족점 중 Text-Play에도 그대로 있는 것

| ChatBot 부족점 | Text-Play의 같은 문제 |
| --- | --- |
| Mock 응답이 캐릭터·맥락을 무시함(고정 3문장) | Mock 서술 2종, 대사는 항상 `lyra` "그 선택을 기억할게.", 액션은 항상 관계 +1. 관계가 100이 되면 자유 입력이 모두 거부됨 |
| `summarizeConversation()`은 계약만 있고 `memories`는 필드만 있음 | 기억 개념이 없음. AI 문맥에 장면 서술·최근 기록이 빠짐(`ai/context-builder.ts`) |
| 랭킹·지표가 Mock | 플레이 수가 코드에 고정됨, 작품 50개가 `준비 중` |
| UI만 있고 동작하지 않는 설정 | 웹에서 해상도 설정이 동작하지 않음 |
| "삭제 전 백업" 규칙이 일부에만 적용됨 | 새 게임의 첫 선택이 기존 자동 저장을 경고 없이 덮어씀(`TextPlayProvider.tsx`) |
| `window.confirm` 사용, 밝은 화면과 어두운 화면 혼재 | 저장·불러오기·삭제 확인이 `window.confirm`. 홈만 밝고 플레이·저장·설정 창은 어두움. 영문 라벨과 챗봇식 문구("저장된 대화가 없습니다")가 남아 있음 |
| 배포 값 미확정 | 버전이 5곳에 따로 적혀 있고 `package.json`만 `1.0.0` |

## 2. Text-Play 핵심 공백

- **엔딩:** `endings[]`의 제목과 요약을 화면에서 쓰지 않습니다. 엔딩 화면이 없고, 엔딩 뒤에도 입력과 전송이 켜져 있어 LLM을 호출한 뒤 거부됩니다.
- **내부 식별자 노출:** `FOREST-GATE`, `lyra`, `moon-lantern`, `voices-below`가 그대로 보이고, 저장 슬롯 요약에는 `moonlit-hall`이 보입니다. 테스트가 이 표시를 정답으로 고정하고 있습니다.
- **작품 1개 고정:** 샘플 패키지가 `src` 6곳에 고정되어 있고, 화면 이동에 작품 ID가 없습니다.
- **콘텐츠:** 장면 5개(엔딩 2개), 장면 서술은 각 1문장, 가장 긴 경로가 선택 3번, 장면 이미지는 임시 SVG입니다.
- **자유 입력 검증:** 설계서(`2026-09-25-text-play-web-mvp-design.md` §11)와 달리 장면별 허용 범위, 변화량 상한, 핵심 이벤트 보호가 없습니다. `trigger-event`·`complete-quest`도 자유 입력으로 확정됩니다.
- **게임 시스템:** 조건부 선택지가 없습니다. `eventFlags`를 읽는 곳이 없고, 능력치가 0이 되어도 게임 오버가 없으며 골드를 쓰는 곳도 없습니다.
- **저장 호환성:** `saveSchemaVersion`·`packageVersion`을 저장만 하고 이전·검사 로직이 없습니다.
- **입력 편의:** Enter 전송이 없습니다. 추천 답안을 펼치면 토글 버튼이 밀려 올라가, 같은 자리를 다시 누르면 답안이 선택됩니다.
- **exe 번들:** 챗봇 자산이 포함되어 `public` 14MB가 통째로 복사됩니다. 이미지 `alt`가 비어 있고 오류 경계가 없습니다.
- **홈:** 기본 화면의 `전체 작품`은 상위 10개를 뺀 목록입니다(`TextPlayHome.tsx:104`).

## 4. 추천 진행 순서

1. **A1 엔딩 화면, A2 표시 이름:** 인수인계 문서 3·4번 항목입니다. 작업이 작고 exe에서 바로 체감됩니다.

4. **C1 작품 ID 구조 → B3 장기 기억 → C3 두 번째 작품:** ChatBot 소개 페이지의 약속을 실제 기능으로 맞춥니다.
5. **A5 디자인 전환, D1·D2 배포:** 결정 1과 결정 5 이후 진행합니다.

## 5. 결정이 필요한 항목

1. **플레이 화면 디자인:** 메인처럼 밝은 다채색으로 바꿀지, 기존 3테마(다크 판타지·SF·비주얼 노벨)를 유지하고 밝은 테마를 추가해 기본값으로 할지
2. **ChatBot 소개 문구:** 장기 기억·같은 LLM·계정 로그인·작품 다운로드를 구현 목표로 둘지, 현재 기능에 맞게 문구를 고칠지
3. **두 번째 작품:** 「황혼 우체국」(애린)으로 할지
4. **올라마 검증:** 이 PC에 올라마를 설치해 실기기 검증을 할지
5. **배포:** GitHub Release 공개 시점
6. **공통 코드:** 두 저장소의 공통 코드(디자인 변수, LLM 계약, `memories` 형식)를 지금처럼 복사로 맞출지, 공유 패키지로 뺄지
