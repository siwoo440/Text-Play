# 로컬 캐릭터 제작·수정·보관함 설계

---

## 1. 목표

외부 API, 데이터베이스, 결제 없이 캐릭터 제작·수정·보관·대화 재진입이 실제로 저장되는 로컬 기능을 완성한다. 현재 MATE:VERSE 디자인 체계를 유지하면서 데스크톱과 모바일에서 자연스러운 편집·보관 흐름을 제공한다.

---

## 2. 범위

- `/characters/new` 새 캐릭터 제작
- `/characters/[id]/edit` 기존 캐릭터 수정
- `/library` 제작 작품·임시 저장·보관 캐릭터·진행 대화
- 캐릭터 상세 화면의 보관 추가·해제
- LocalStorage 저장·복원과 기존 데이터 마이그레이션
- 저장·삭제·탭 전환·보관 상태의 짧은 화면 연출

실제 이미지 업로드, 외부 이미지 생성, 인증, 서버 동기화는 포함하지 않는다. 대표 이미지는 프로젝트에 포함된 로컬 캐릭터 이미지 중에서 선택한다.

---

## 3. 경로와 화면

### 3.1 캐릭터 제작·수정

`CharacterEditor`는 제작과 수정 화면에서 공통으로 사용한다. 입력 항목은 이름, 한 줄 소개, 상세 설명, 성격, 첫 인사, 세계관, 제작자용 비공개 프롬프트, 태그, 대표 이미지, 공개 범위다.

데스크톱에서는 입력 폼과 고정 미리보기를 2열로 배치한다. 모바일에서는 입력 폼 다음에 미리보기를 배치한다. 입력 내용은 카드와 첫 메시지 미리보기에 즉시 반영한다.

사용자는 `임시 저장` 또는 `공개 저장`을 선택한다. 수정 화면은 기존 데이터를 채우며 저장되지 않은 변경 사항이 있는 상태에서 경로를 벗어나면 확인을 표시한다.

### 3.2 보관함

`LibraryScreen`은 다음 탭을 제공한다.

- 내 캐릭터
- 임시 저장
- 보관 캐릭터
- 진행 중인 대화

내 캐릭터와 임시 저장 카드에서는 수정·삭제·공개 상태 변경을 제공한다. 보관 캐릭터에서는 보관 해제와 대화 시작을 제공한다. 진행 중인 대화에서는 최근 메시지와 관계 단계를 표시하고 채팅으로 이동한다.

빈 탭에는 다음 행동으로 이어지는 안내와 버튼을 표시한다.

### 3.3 캐릭터 상세

기존 `보관함 추가` 버튼을 실제 토글로 교체한다. 보관 여부는 새로고침 뒤에도 유지하며 버튼의 접근 가능한 이름과 시각 상태를 함께 바꾼다.

---

## 4. 데이터 구조

`Character`에 `publicationStatus: "draft" | "published"`를 추가한다. `AppState`에 `bookmarkedCharacterIds: string[]`를 추가하고 `schemaVersion`을 2로 올린다.

스키마 1 데이터는 다음 규칙으로 스키마 2로 변환한다.

- 기존 캐릭터는 모두 `published`
- 보관 목록은 빈 배열
- 기존 프로필·캐릭터·대화·메시지·지갑·설정은 그대로 유지

마이그레이션 실패 시 원본 문자열을 복구 키에 보존하고 초기 Mock 상태를 사용한다.

Reducer는 다음 동작을 제공한다.

- 캐릭터 생성·수정
- 캐릭터 삭제와 연결 대화·메시지 정리
- 캐릭터 보관 추가·해제
- 공개 상태 변경

편집 폼의 로컬 상태를 검증한 뒤 Reducer에 전달하고 `AppProvider`가 전체 상태를 LocalStorage에 저장한다.

---

## 5. 검증 규칙

- 이름: 필수, 공백 제외 1~40자
- 한 줄 소개: 필수, 1~80자
- 성격: 필수, 1~500자
- 첫 인사: 필수, 1~1000자
- 상세 설명·세계관·비공개 프롬프트: 각각 최대 2000자
- 태그: 최대 8개, 각 태그 12자 이하, 공백과 중복 제거
- 대표 이미지: 허용된 로컬 이미지 경로만 사용
- 공개 저장은 공개 범위를 사용하고 임시 저장은 탐색 화면에 노출하지 않음

모든 검증 오류는 한 번에 계산해 각 입력란 가까이에 표시한다. 오류가 있는 상태에서는 저장하지 않는다.

---

## 6. 오류와 복구

- 존재하지 않는 캐릭터 수정 경로는 전용 안내 화면 표시
- LocalStorage 저장 실패 시 현재 입력 유지와 오류 안내
- 삭제 전 캐릭터 이름을 포함한 명시적 확인
- 캐릭터 삭제 시 연결 대화와 메시지 함께 정리
- 제작자용 비공개 프롬프트는 일반 상세·탐색·보관 카드에 미노출
- 마이그레이션 실패 원본은 즉시 삭제하지 않고 복구 사본 유지

---

## 7. 화면 연출과 접근성

- 카드 등장과 탭 전환은 160~220ms 페이드·이동 효과 사용
- 저장 성공은 토스트와 버튼 상태로 전달
- 보관 토글은 아이콘·문구·배경색을 함께 변경
- 삭제 확인은 키보드로 조작 가능한 대화상자 사용
- 모바일 터치 영역은 최소 44px
- `prefers-reduced-motion`에서는 전환 효과 제거
- 모든 입력과 버튼에 접근 가능한 이름 제공
- 오류와 저장 완료 상태는 라이브 영역으로 전달

---

## 8. 검증 전략

단위 검증은 입력 검증, 태그 정규화, 보관 Reducer, 삭제 정리, 스키마 1→2 마이그레이션을 다룬다.

통합 검증은 다음 흐름을 다룬다.

- 입력 → 미리보기 → 임시 저장
- 공개 저장 → 홈과 보관함 노출
- 기존 캐릭터 수정 → 새로고침 뒤 유지
- 상세 화면 보관 → 보관함 노출 → 보관 해제
- 삭제 확인 취소와 승인
- 비공개 프롬프트 비노출

화면 검증은 데스크톱 2열, 모바일 단일 열, 빈 상태, 오류 상태, 애니메이션 감소, 키보드 접근성을 확인한다.

---

## 9. 완료 기준

- 새 캐릭터를 임시 또는 공개 상태로 저장 가능
- 저장한 캐릭터를 수정하고 새로고침 뒤 복원 가능
- 상세 화면에서 보관 상태를 변경하고 보관함에서 확인 가능
- 보관함의 네 탭이 실제 로컬 상태와 연결
- 캐릭터 삭제 시 연결 데이터가 일관되게 정리
- 기존 스키마 1 데이터가 손실 없이 스키마 2로 변환
- 단위·통합 테스트, 타입 검사, ESLint, 프로덕션 빌드 통과
